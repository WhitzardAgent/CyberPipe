# FIM-Midtraining-400K

[📄 Paper](https://arxiv.org/abs/2607.12463) · [💻 GitHub](https://github.com/TIGER-AI-Lab/FIM-Midtraining) · [🤗 Collection](https://huggingface.co/collections/TIGER-Lab/fim-midtraining)

The mid-training corpus of **"Function-Aware Fill-in-the-Middle as Mid-Training for Coding Agent Foundation Models"**: **400K function-aware FIM samples (~2.6B tokens** under the Qwen2.5-Coder tokenizer) drawn from **75,568 Python files across 968 permissively-licensed GitHub repositories**, fully decontaminated against SWE-Bench.

A coding agent's inner loop — *act → observe → continue* — is structurally isomorphic to a function call site: a caller binds arguments, a callee returns a value computed elsewhere, and downstream code consumes that value. This corpus exploits that isomorphism. Instead of masking random spans, we mask **functions** — selected by program-dependency-graph analysis and a complexity–inferability double criterion — and train the model to recover them from the surrounding file, reasoning first.

Mid-training Qwen2.5-Coder-7B/14B-Instruct and Qwen3-8B on this corpus before agentic post-training (R2E-Gym / SWE-Smith / SWE-Lego, unmodified) improves SWE-Bench-Verified by **+2.8 / +3.0 / +3.2** and SWE-Bench-Lite by **+3.7 / +4.0 / +5.4**, while restoring most of the general-capability erosion that agentic post-training otherwise inflicts (LiveCodeBench +11.1, τ-bench +3.9, BFCL +2.4 at 14B).

## Splits

| Config | Samples | What is masked | Tokens | File |
|---|---|---|---|---|
| `all_merged` (default) | 400,000 | 80% single / 15% pair / 5% triple mixture — **the corpus used for the paper's main results** | ~2.63B | `all_merged_400k.jsonl` (12.4 GB) |
| `single_function` | 320,000 | one function body per file | ~2.0B | `single_function_320k.jsonl` (9.7 GB) |
| `function_pair` | 60,000 | two structurally coupled functions, jointly | ~0.4B | `function_pair_60k.jsonl` (1.9 GB) |
| `function_triple` | 20,000 | three structurally coupled functions, jointly | ~0.2B | `function_triple_20k.jsonl` (0.8 GB) |

`all_merged` is exactly the union of the three splits (320K : 60K : 20K = 80 : 15 : 5), shuffled. Per-split corpus statistics ship alongside each file as `*_stats.json`.

## Format

Each line is one JSON record ready for chat-format SFT (LLaMA-Factory `sharegpt`):

```json
{
  "messages": [
    {"role": "user",      "content": "You are an expert Python programmer. ... ## Code with Masked Function\n\n```python\n<file with one or more bodies replaced by  # <MASKED_FUNCTION_BODY>>\n```"},
    {"role": "assistant", "content": "### Reasoning\n<step-by-step analysis>\n\n### Implementation\n```python\n<function body>\n```"}
  ],
  "metadata": { ... }
}
```

- The **user turn** contains the complete source file with the selected function body (or 2–3 coupled bodies) replaced by `# <MASKED_FUNCTION_BODY>`, plus fixed instructions.
- The **assistant turn** contains a step-by-step rationale followed by the implementation — mirroring the think-then-act structure of an agent step. Rationales were generated by Gemini-3-Flash **from the masked context only** (no access to the ground-truth body) and kept only if a separate LLM judge scored the pair highly against the ground truth on feasibility and five quality dimensions.

`metadata` carries full provenance and selection scores per sample: `repo_id`, `repository_url`, `file_path`, `func_name`, `start_line`/`end_line`, `loc`, `category`, `quality_rating`, `graph_stats` (dependency-graph context), the selection scores (`complexity` Ĥ, `inferability` Î, `fim_score`, `difficulty`), and the judge scores (`overall_score`, `correctness`, `executability`, `api_usage`, `readability`, `completeness`). The per-repository license joins via `repository_url` against the [repository list](https://github.com/TIGER-AI-Lab/FIM-Midtraining/blob/main/data_construction/data/code_repo_list_968.csv).

## How targets were selected

Not at random. For every function in every file we build a program dependency graph (call edges + same-class sibling edges) and compute two scores:

- **Complexity Ĥ** — LoC, cyclomatic complexity, nesting depth: is the function worth predicting?
- **Inferability Î** — call-site specificity, in-file callees, signature, docstring, class siblings: is it recoverable from context?

A harmonic-mean-like combination `FIM(v) = Ĥ·Î/(Ĥ+Î) · ρ(Δ)` keeps targets that are *both* substantial and recoverable, and a one-sided penalty ρ suppresses targets that stay hard even with full context. Multi-function groups (pairs/triples) are selected over eight coupling topologies (caller–callee, sibling-coupled, class-triad, co-callee, fan-in, hub, call-chain, mutual-call) with the group's inferability recomputed under joint masking. The full algorithm, constants, and a worked example are in the paper's Appendix B; the complete pipeline is released at [`data_construction/`](https://github.com/TIGER-AI-Lab/FIM-Midtraining/tree/main/data_construction).

## Decontamination

- Zero overlap with SWE-Bench source repositories (checked by repository name and known forks).
- Every repository is restricted to commits **before the earliest base commit of SWE-Bench-Verified/Lite**, eliminating test-time leakage.

## Usage

```python
from datasets import load_dataset

ds = load_dataset("TIGER-Lab/FIM-Midtraining-400K", "all_merged", split="train")   # main corpus
single = load_dataset("TIGER-Lab/FIM-Midtraining-400K", "single_function", split="train")
```

To mid-train with [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory), download the JSONL into its `data/` directory and register it as a `sharegpt` dataset — the exact `dataset_info.json` entries, the reference training config, and per-model as-run configs are in [`midtraining/`](https://github.com/TIGER-AI-Lab/FIM-Midtraining/tree/main/midtraining) of the official repo:

```bash
huggingface-cli download TIGER-Lab/FIM-Midtraining-400K all_merged_400k.jsonl \
  --repo-type dataset --local-dir <LLaMA-Factory>/data/
```
