# 调研笔记 06：图文数据落点决策分析——"文本为主、图文为辅"（PLAN v1.2 决策依据）

> 调研/讨论日期：2026-09-29。前置决策：基座为多模态模型；目标 agent scaffold = Claude Code / Codex。
> 本笔记是 PLAN.md v1.2 中 S2a/S8/S10/6.3 决策记录的完整论证版。

## 一、问题

基座是多模态模型，而安全网页数据大量图文交错（终端截图、网络拓扑图、代码截图、漏洞复现截图）。mid-training 的图文数据应该做成**交错（interleaved）**还是**纯文本（全部文本化）**？要求给出有确定性研究依据的判断。

## 二、结论

**安全数据 100% 文本化进入 mid-training；图像分支按"数据资产生产线"建设（过滤/去重/OCR/caption/存储照常做，交错开关保留）；另设通用多模态回放 3–5% + 可选安全图文切片 0–2%（由实验决定）。**

不是折中，而是现有证据下确定性最高的路径：主路径选有全量证据支撑的一侧（文本），把另一侧做成可翻转的资产，再用两个便宜实验收口剩余不确定性。

## 三、证据

### 3.1 agentic mid-training 的全部公开证据建立在文本观测上

| 工作 | 观测/输入形态 | 有图像参与吗 |
|---|---|---|
| MidTool（20.3B，arXiv 2608.20314） | 网页/PDF/代码全文本化，轨迹是 API 调用文本 | 无——**连 PDF 都 OCR 文本化**（schema 含 `ocr_quality_scores` 字段） |
| Meta CWM（5T MT，arXiv 2510.02387） | bash/文件编辑文本轨迹 + Python 执行轨迹 | 无 |
| Kimi-Dev（150B，arXiv 2509.23045） | diff/PR 文本 + 非执行工具模拟轨迹 | 无 |
| AgentFounder（~300B，arXiv 2509.13310） | 知识记忆 + 文本合成轨迹 | 无 |
| State2State（arXiv 2608.04934） | 环境观测文本（MobileWorld 的截图只在奖励侧用隐藏 XML，策略侧仍是文本观测） | 无（策略可见面为文本） |
| FIM-Midtraining / daVinci-Dev | 纯代码/PR 文本 | 无（两仓库均无多模态路径，代码级核验确认） |

"mid-training 提升 agentic 能力"这一命题，目前**没有任何已发表证据是靠图像输入建立的**。唯一 in-loop 消费像素的 agent 家族是 computer-use/GUI（截图进入观测循环）——与目标 scaffold 不同族。

### 3.2 scaffold 观测空间对齐（P4 原则的推论）

Claude Code / Codex 的 in-loop 观测是文本 `tool_result`（bash 输出、文件内容、编辑回执）；图像只出现在用户主动贴图的交互场景，不在核心循环里。Qwen3-Coder-Next（arXiv 2603.00729）证明训练数据形态与目标 scaffold 失配时迁移有限——给终端 agent 喂大规模交错图像，训练分布与推理分布对不上。

### 3.3 安全图像的内容可文本化率高

- 终端截图/代码截图（安全页面图像大头）：本质是文本，OCR 保真率预期 >90–95%（待 S10 实验 1 实测确认）。
- 拓扑图/架构图：真正不可文本化（空间结构），但终端 agent 的工作流中以命令输出（nmap、配置文件）形态出现，不依赖读图。
- Qwen3-Coder-Next Table 1：内容保持型文本化本身就是提升代码能力的杠杆（Evalplus 54.38→63.09、MultiplE 36.02→48.35）。

### 3.4 交错无害，但对症性差

- [MINT-1T](https://arxiv.org/abs/2406.11271)：在交错数据上训练的模型在**纯文本和多模态基准上同时超过** OBELICS 系——交错对文本能力中性偏正。
- [OmniCorpus](https://arxiv.org/html/2406.08418v3)：消融显示交错混合维持 MMLU 等纯文本成绩；典型 VLM 配方 ~40% 纯文本 + ~35% 交错 + ~20% caption。
- 结论：交错买到的是**多模态技能**（图文 few-shot、读图、视觉 grounding），对 Claude Code/Codex 的 agentic 核心循环没有贡献——花预算买不对应目标的能力。

### 3.5 成本结构

一张 1024² 图通常消耗数百至上千 token（取决于基座视觉编码方案），是同页面文本的 3–10 倍。高质安全语料仅 1–5B token、预算 20–50B——大规模交错会让图像 token 吃掉预算的 30–50%，挤走已被证明有效的杠杆（轨迹、FIM、仓库级代码）。

### 3.6 多模态基座的风险在反方向，且有标准解法

- 纯文本 mid-training 会让视觉通路漂移/遗忘：[Aya Vision](https://www.alphaxiv.org) 明确记载模态间灾难性遗忘，并以"simulate model merging"（文本模型与多模态模型检查点融合）解决；[CTP（CVPR 2023）](https://openaccess.thecvf.com/content/CVPR2023/papers/Chen_Towards_Vision-Language_Continual_Pretraining_via_Complementary_Modalities_CVPR_2023_paper.pdf) 系统研究 vision-language continual pretraining 的遗忘；反向（多模态训练伤文本）见 NeurIPS 2024 "Learning Multimodal LLMs without Text-only Forgetting"。
- 解法三层，都比"大规模交错安全数据"便宜且对症：
  1. 通用多模态回放 3–5%（CWM "回放防遗忘"的多模态版）；
  2. vision encoder 冻结或低 LR（跨模态 grounding 主要在 LLM 侧）；
  3. 兜底：视觉能力回退时用 Aya/PRISM 式检查点合并（PRISM：15/85 合并把 RULER 6.46→42.16）。

## 四、落点（对 PLAN 的具体修改）

1. 安全数据 100% 文本化：终端/代码截图走 OCR；拓扑图走 VLM 结构化描述；所有 OCR/caption 文本进入文本流与全部过滤器（质量、安全、去污染）。
2. 安全图文切片 0–2%（可选）：截图类文档"原图+OCR/caption 双信号"，服务"用户往 Claude Code/Codex 贴截图"交互；是否保留由实验 2 决定。
3. 通用多模态回放 3–5% 保护视觉通路。
4. 图像分支作为资产生产线照常建设：交错开关保留，哪天做截图理解/GUI 方向，翻配置即可产出交错版本。

## 五、两个收口实验

**实验 1：OCR 信息保留率审计（零训练成本，P2 交付）**
- 用自建 500–1000 张安全截图内部评测集（S2a 已规划），分类测量文本化保真率。
- 预期：终端/代码截图 >90–95%；拓扑图损失大。
- 产出兼作 S10 图文探针集。

**实验 2：A/B microanneal（一次 ~10B token，P4 执行）**
- A = 纯文本安全 MT；B = 同文本内容 + 截图文档交错（B 的图像 token 计入预算）。
- 固定 SFT，四组探针：文本 agentic（bash 工具调用）/ 截图读图（截图→命令抽取）/ 通用视觉回归 / 通用文本回归。
- 决策规则：
  - A≈B 全线 → 定案纯文本（省成本）；
  - B 仅截图探针显著胜出 → 保留 0–2% 安全图文切片；
  - B 在文本 agentic 上掉点 → 纯文本 + 上调多模态回放。
