# 调研笔记 01：工程骨干与质量过滤（datatrove / dolma / Dolmino / MegaMath / MIRA / SmolLM3）

> 子任务报告存档，调研日期 2026-09-29。克隆仓库位于 `research/repos/{datatrove, dolma, OctoThinker, MegaMath}`。

## ① 工程骨干选型：datatrove 做骨干，dolma 只借鉴设计

| 维度 | datatrove (HF) | dolma (AllenAI) |
|---|---|---|
| 抽象 | `PipelineStep`（`src/datatrove/pipeline/base.py`）串联生成器；Executor 分 `local/slurm/ray/jobs` | Python taggers + Rust 引擎（`dolma tagger/dedup/mix/tokenizer`） |
| HTML 抽取 | `Trafilatura`（`favour_precision=True, timeout=1s, deduplicate=True`）和 `ReadabilityInscriptis`。**无 resiliparse** | `ResiliparseHtmlExtractor`（`preserve_formatting=True, main_content=True`） |
| 去重 | `minhash.py`：`MinhashConfig(n_grams=5, num_buckets=14, hashes_per_bucket=8)`（FineWeb 用 9 buckets），Signature→Bucket→FinalFilter 三阶段；另有 `exact_substrings.py`(EDS)、`sentence_dedup.py`、`bloom_filter.py` | Rust `deduper.rs`：bloom filter + n-gram，另有段落去重配置 |
| PII | `formatters/pii.py`：正则替换式，直接改 text | `taggers/pii.py`：只写 span 到 attributes，替换延迟到 mix 阶段 |
| 分类器打分 | `pipeline/inference/run_inference.py`（vLLM servers + RequestCache，每 6000 条一档）；fasttext 走 `filters/fasttext_filter.py` | `core/ft_tagger.py` 内置 `train_supervised` 可现场训 fasttext；结果一律落 attributes |
| 断点 | 任务级 `LocalPipelineExecutor(skip_completed=True)` | 按 shard 断点续跑（Rust 侧） |
| 输出 | jsonl.gz / parquet / HF hub，分数进 `Document.metadata` 内联 | W3C-IDO：正文与 `attributes` 分离，文本不可变 |

### "代码块保留"核验结论（关键差异点）
- **trafilatura 会破坏代码块**（本机实测 2.0.0）：`<pre><code>` 输出被压平为单行；`include_formatting=True` + markdown 也无代码围栏、无换行；**没有 include_code_blocks 参数**。对"代码+图文交错"语料是硬伤。
- **resiliparse**：`extract_plain_text(preserve_formatting=True)` 保留块级格式，对 `<pre>` 行结构保留远好于 trafilatura（dolma 默认即开启）。
- **推荐做法**：datatrove 里写自定义 `BaseExtractor`：先用 lxml/xpath 抽出全部 `<pre><code>` 节点替换为占位符 → trafilatura 抽正文 → 占位符处回填围栏代码块；或直接用 dolma 式 resiliparse。保留原始 HTML 于 metadata，为重抽取留路（MegaMath 同款思路）。

### 选型结论
- **骨干 = datatrove**：Python 生态贴合自有过滤器；MinHash 三阶段与任务级断点；`InferenceRunner` 承接 LLM 评分器；输出简单。
- **借鉴 dolma 4 点**：(a) attributes 分离存储（分数与正文解耦、正文不可变，调阈值不重跑）；(b) PII 打标延迟到 mix 阶段替换；(c) `dolma mix` 的 per-source 流混合器；(d) resiliparse 抽取器做代码块友好对照实现。

## ② 推荐过滤栈（规则→分类器→去重，全分数存 metadata）

原则：便宜在前、昂贵在后；**打分与丢弃解耦**（先打分存档，阈值后置）。

| # | 步骤 | 模块 | 建议阈值 | metadata |
|---|---|---|---|---|
| 1 | URL 过滤 | `URLFilter` + 白名单 | 域名黑名单 + 安全站点白名单 | `url_passed` |
| 2 | 抽取 | 自定义 PreSpliceTrafilatura | `favour_precision=False` | 原始 HTML、code_block_count |
| 3 | 语言 ID | fasttext `lid.176.bin` | score ≥ 0.65，非 en/zh 降权不丢弃 | `lang`, `lang_score` |
| 4 | 规则质量 | `FinewebGopherQualityFilter` + `GopherRepetitionFilter` | Gopher 默认值 | `gopher_pass`, `repetition_ratio` |
| 5 | 领域分类 | fastText 领域分类器（MegaMath 模式） | 自行标定，≥0.5 保留、≥0.9 高分桶 | `domain_score` |
| 6 | LLM 通用质量 | FineWeb-Edu 式 3B 评分器（0–5） | ≥3 高质量、2–3 可用、<2 丢弃（OLMo2：≥3 仅留 5.8%） | `edu_score` |
| 7 | 源感知评分 | MIRA 式 per-source-group 评分器（可选） | per-group 阈值，trim-mean | 各维度分 0–10 |
| 8 | MinHash 去重 | 三阶段 | `n_grams=5, hashes_per_bucket=8, num_buckets=9`；Jaccard 0.7–0.8 | `dup_flags` |
| 9 | 跨源/精确去重 | EDS 或 dolma bloom n-gram | 先跨源去重再混合；13-gram 去污染 | — |
| 10 | PII | datatrove `PIIFormatter` 或 dolma span 式 | email/IP/key；安全语料加密钥/漏洞 URL 扩展 | `pii_spans` |
| 11 | 混合 | `SamplerFilter` 或 dolma mix | per-source 权重按 Dolmino 配方 | — |

去重放在分类器之后：高分文档才值得付去重成本（FineWeb 顺序）。

## ③ Dolmino / MegaMath / MIRA 可搬走的具体做法

**Dolmino（OLMo 2，arXiv 2501.00656 §4；卡片 allenai/dolmino-mix-1124）**
1. 双分类器 web 质量闸：DCLM fastText（阈值 0.03311014，留 65.6%）∧ FineWeb-Edu ≥2（留 20.3%）→ 752B 高分 web 池。两个分数都存档。
2. 混合公式：DCLM ≈50% token + 其余源 50%；稀缺源用"Source%"表示重复倍数（100B 混合中 StackExchange=200%、Stage2Math=200%；300B 档 Wiki/Math 400%）。
3. LR 线性衰减到 0；7B 用 3 个 50B 不同数据序检查点做**模型平均**。

**Dolmino（Olmo 3，arXiv 2512.13961；卡片 dolma3_dolmino_mix-100B-1125）**
4. 100B mid-mix：HQ-CC 22.4B(22.5%) + StackEdu-FIM 10B + CraneCode 10B + Dolmino Math 10.7B + QA/Thinking 合成（池 2.19T 取 99.95B）。
5. **microanneal 验证法**：候选数据集用 5B 目标数据 + 5B web 各 10B 退火快速对比再决定是否入池——小成本选源，强烈推荐搬用。
6. fastText 质量分类器正例 = OpenHermes-2.5/ELI5/UltraChat/WildChat，负例 = DCLM-RefinedWeb，按分位 20 桶（vigintile）；上采样封顶 **7x**。
7. PDF 侧：>30% 表格或 >20% 数字的文档直接丢；MinHash 75% 相似度（仅去 2.3%）。

**MegaMath / OctoThinker（repos/MegaMath/web_pipeline/；卡片 OctoThinker/MegaMath-Web-Pro-Max）**
8. 三段式：Stage1 下载+抽取+LID(0.65)+数学 fasttext(0.95)；Stage2 去重复用 datatrove minhash 改 `(num_buckets=11, hashes_per_bucket=10)`；Stage3 重抽取。
9. **Pro-Max 精修五步**：按发表年份分层抽样 → Llama-3.1-70B 用 FineMath prompt 打标 → 用标注训 fasttext（预处理去符号/数字归一，`utils/math_fasttext.py`）→ 阈值 0.4 过滤 → 70B LLM 规模化改写（refine）。"小模型粗筛 + 大模型精修头部数据"是性价比范式。
10. OctoThinker 仓库本身无数据管线代码，管线在 LLM360/MegaMath 与 HF 卡。

**MIRA（arXiv 2605.30288；评分器 `whw06/MIRA-{QA,Text,Agent}-Group{1..5}`）**
11. 全流程：源 embedding 均值聚类成 5 组 → 教师（Kimi-K2.6）自由提名质量维度，judgment points KMeans k=15 取质心最近点为**锚定维度** → 教师按锚重打大样本 → 蒸馏为 per-group 学生评分器：**Qwen3.5-35B-A3B-Base 全参微调（~2M 样本/组），输出每个锚的 (维度名, 0–10 整数分, 理由)**。
12. 可靠性聚合：学生-教师 MAE ≥1 的 (源×维度) 格子置零，余下维度 trim-mean；per-source-group 保留阈值。
13. 效果：Qwen2.5-Coder-14B，50B 池选 25B（**一半 token 达全量效果**），macro 64.20 vs 原始 63.83、Random 63.23。对多源异构语料（漏洞库/教程/论文/代码）是最贴合的评分架构；贵在教师标注，学生推理可离线批量跑。

## ④ SmolLM3 mid.yaml 摘录（alignment-handbook/recipes/smollm3/sft/mid.yaml）

- `SmolLM3-3B-Base`，bf16 + flash_attention_2；mid-training 以 SFT 形式做。
- 数据：`HuggingFaceTB/smoltalk2` 配置 `Mid`，两个 reasoning 源等权：`Llama_Nemotron_Post_Training_Dataset_reasoning_r1` + `OpenThoughts3_1.2M`。
- 训练：`learning_rate: 2.0e-05`，`cosine_with_min_lr (min_lr_rate: 0.1)`，`num_train_epochs: 5`，`packing: true`，`max_length: 32768`，`warmup_ratio: 0.03`，`max_grad_norm: 0.2`，GBS 128（8 节点），Liger kernel，每 0.05 进度存档。

**一句话结论**：datatrove 骨干 + 自研 `<pre>` 保留抽取器；规则(Gopher/lid/domain-fasttext) → FineWeb-Edu 式 LLM 打分（存 metadata 后置阈值）→ MinHash(5-gram/9 buckets) → 跨源 EDS；混合按 Dolmino 配方（HQ web 50% + 稀缺源重复 ≤7x），候选集用 5B microanneal 验证；源异构严重时上 MIRA 式 per-group 评分器。
