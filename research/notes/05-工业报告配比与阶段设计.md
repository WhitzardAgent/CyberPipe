# 调研笔记 05：工业 mid-training 报告——配比、阶段、loss mask、评测协议

> 子任务报告存档，调研日期 2026-09-29。8 篇论文关键细节已核验（含 CWM Table 4 消融原始数据）。

## 1. Meta CWM（arXiv 2510.02387，§4.2 / §2.2–2.3 / §7.1 Table 4）

- **混合结构**：8T 预训练（代码 30%）+ 5T mid-training。MT 内 **30% CWM 专项 + 40% 通用代码 + 30% 预训练回放**；回放"对保持标准评测性能不可或缺"，回放内**上采样数学与长上下文数据、避免过 epoch**。SFT 中也保留 ~30% 来自 MT 的回放 → 通用回放贯穿 MT 与 SFT 是可操作默认值。
- **专项 30% 的构成**：① ForagerAgent 环境交互轨迹：3M 条轨迹 / 10.2k 仓库镜像 / 3.15k 仓库，55% issue-fix + 45% mutate-fix，动作=SWE-Agent 式（bash、文件编辑、查看）；② Python 执行轨迹：>120M 函数级 trace、33k CodeContests 片段+70k 轨迹、70k 提交级仓库轨迹；③ SWE-RL 式 GitHub PR、编译器 IR、Triton kernel、Lean 形式化数学。各子集不定固定百分比，用 **scaling-law 模拟 epoching 定每数据集 1–4 个目标 epoch**，再反推混合比例。
- **不可替代性消融（Table 4，8B：6T 预训练 + 1T 消融 MT + 相同 SFT，无 RL）**：

| 配置 | CruxEval-O | CruxEval-I | Oracle SBV NLL | Agentic SBV NLL | SBV pass@1 |
|---|---|---|---|---|---|
| 无专项 | 45.4 | 44.1 | 0.64 | 0.39 | 14.6 |
| +PR | 44.6 | 45.8 | 0.55 | 0.37 | 18.6 |
| +PR+执行轨迹 | 73.9 | 51.5 | 0.54 | 0.38 | 18.4 |
| +PR+轨迹+Forager | 74.5 | 54.8 | 0.54 | **0.29** | **22.1** |

  结论：**PR 数据只改善 oracle-patch NLL 和 pass@1，不改善 agentic NLL 与执行理解**；执行轨迹把 CruxEval-O 45.4→73.9 但完全不动 SBV；**只有环境交互轨迹能把 agentic NLL 0.39→0.29 并额外 +3.7% SBV**。每类数据映射到各自能力族；agentic 能力无法用静态代码/PR 替代。
- **轨迹 loss 设计**：agent 轮与 environment 轮**都算 loss**（联合学习世界模型），但观测轮"多样性有限"，**随机 mask 50% 的观测轮 loss**；不按成败过滤轨迹；按动作序列 MinHash 近重去重（Jaccard<0.5）防过拟合。
- **长上下文**：MT 直接全称 131k 上下文，~30% 文档 >65k token，**无需单独长上下文阶段**；长上下文数据必须配大 batch（33M token），小 batch "lackluster performance"；按长度分桶（16k/65k/∞）调度并保持数据集边际采样概率不变。

## 2. Kimi-Dev（arXiv 2509.23045）

- **150B MT 组成**（Qwen2.5-72B-Base 起点）：**~50B agentless 数据**（自然 diff patch 改写为 SEARCH/REPLACE 块格式）+ **~20B PR commit packs**（commit message=推理、代码修改=动作，配对监督）+ **~20B 合成数据**（10B 定位专用推理：轻 SFT 模型 rollout 后仅保留定位精确正确的；10B 非执行工具集模拟 agentic 轨迹）。**合成部分 4× 上采样**。过滤：仓库 ≥5 星、剔除 SWE-bench 仓库、只留 {.py,.md,.rst}、每 PR ≤3 个 Python 文件、≤5 个编辑块。
- **Loss mask 双轨制**：agentless 数据 **mask 整个 prompt**、只监督响应；agentic 轨迹数据 **只 mask system prompt**，"enable the model to simultaneously learn both actions and observations" → **环境观测参与监督**。
- **固定后续训练的预算结论**（§3.5.2 Fig 2）：50B/100B/150B MT 后接完全相同的 2000 条 Bugfixer SFT cold start → token 数单调改善。
- **MT=技能先验的量化**：有 MT 先验达到 Base-prior 最高 pass@1 只需 2²³ SFT token，Base 需 1.5×2²⁸；RL 先验版可持续改善到 70+ 轮。

## 3. Qwen3-Coder-Next（arXiv 2603.00729）

- **~600B 仓库级代码数据组织**：file-level + 仓库级（特殊 token 拼接）+ PR + 整仓库 + code review；370 语言；结论 "repo-level 数据是 MT 配方的主要部分，比只用 file-level 更有效"；**混用多种仓库序列化格式**以泛化项目布局；上下文 32,768→262,144。
- **网页处理对代码能力（Table 1）**：低质网页由 480B 模型改写为干净 Markdown（去广告/HTML 痕迹/代码切换）→ **Evalplus 54.38→63.09、MultiplE 36.02→48.35、CRUX-Eval 57.13→58.94**。但 Wikipedia 风格改写"有时引入幻觉引用/URL"→ **只保留内容保持型改写**。
- **跨 scaffold 迁移（§3.1.2 Fig 3）**：6 种 scaffold（SWE-agent、Mini-SWE-agent、OpenHands、Claude-Code、Qwen-Code、Terminus）× ~800K 合成任务、教师 480B。同 scaffold 内 token 越多越好；**"cross-scaffold transfer remains limited"**且不对称 → **轨迹要覆盖目标 scaffold 为主，混合少量其他**。
- **自然 vs 合成**：以自然数据为主体，只引入"可靠完成常见任务所需的最少量合成数据"；纯合成过多 → 过特化、响应多样性下降。MT 以自然文档为主时，**混入少量指令跟随数据以便训练早期监控下游行为**。
- **补充 loss 规则**（§3.2）：mask 高度重复片段（重复代码头/配置块）。

## 4. Step-DeepResearch（arXiv 2512.20491，§4.1 Table 1–3）

- **Stage 1（32K ctx，~150B tokens）**：只注入四类"研究能力"——规划/任务分解、信息获取、反思/验证、报告生成；**明确不引入工具调用**。数据：主动阅读通识/学术（QA+改写双形式）、合成知识、摘要、推理、反思；增益 +1.26 SimpleQA / +2.30 TriviaQA / **+10.88 FRAMES**。
- **Stage 2（128K ctx）**：引入**显式工具调用**与真实复杂任务；数据：URL QA、Deep Search 轨迹、网页浏览轨迹、规划、长文/长对话摘要、长程推理、反思、**通用对话**。
- 切换依据：定性"Stage 1 能力稳定收敛"。
- 可操作规则：先无工具知识/推理阶段、再工具+长上下文阶段；每阶段保留反思与摘要数据；长上下文扩展与工具引入绑定同一阶段。

## 5. K-EXAONE 2.0（arXiv 2608.04505，§4.1–4.4，Table 5）

- **两阶段各 400B**：8K→64K→256K 渐进；**长上下文样本占比随窗口扩展同步提高**；Stage 2 同时加重长推理、仓库级代码、agentic 工作流。
- 数据组成：① 端到端长上下文语料（完整文档、大型仓库、长工具/交互轨迹，"minimal truncation"）；② 合成多跳数据（跨远距离上下文定位-连接-综合）；③ 高难推理（STEM 分类器 + **内部搜索 agent 挖掘的高难知识**，**从 Mid-Stage 2 才引入**）；④ Agent 工作流：按能力分类的工具轨迹 + GitHub PR 五元组（PR 描述+patch diff+reviewer 评论+文件+commit 历史）；⑤ 工具格式：XML 为主 + 多模板混合，保证格式不变性。
- 长上下文课程依据：长上下文适配是 agentic 能力的"critical foundation"→ **长上下文数据放在 agentic 数据之前/伴随，而非最后阶段**；NIAH 256K 全满分。
- 阶段消融（Table 5，小模型，HLE）：MS1→SFT +3.15；MS1→MS2 +4.71；**MS1→MS2→SFT +5.66** → Stage 2 相对直接 SFT 有 +0.95 互补增益。

## 6. CMU：Midtraining Bridges Pretraining and Posttraining Distributions（arXiv 2510.14865）

- 设计：Pythia 70M–1B，C4 128B 预训练；MT 候选：Starcoder(196B)、Math(12B)、FLAN(3.5B)、KnowledgeQA(9.6B)、DCLM(51B)；对照=同 token 数继续 C4。
- **领域特异性**：收益集中在与后训练目标"距离远"的领域：代码 MT 使 Pycode SFT loss 2.174→1.888；**FLAN/广谱指令与 QA 类 MT 对代码/数学几乎零收益（≤0.006）**→ 指令/QA 数据不能替代领域数据做衔接。
- **混合优于纯领域续训（Table 3）**：160M 模型上 Starcoder 20% 混合 = SFT 2.134/C4 5.079，优于 100% Starcoder（2.219/5.369）与纯预训练 → **MT 内保留通用数据混合是必需品**。
- **引入时机 × 权重**：早引入 + 高权重（80%）最好；晚引入 + 80%"显著差于 10% 保守混合"；**渐进补偿（10%→20%→30%）失败** → 存在可塑性窗口，**领域数据应早进、大胆进**。域内收益 ~6k 步即现，遗忘保护收益 ~20k 步才现。
- 小规模实验注意：结论来自 70M–1B，外推存疑；Proximity-Advantage 预测力随规模变化；**保留效应时间滞后 → 短跑会低估 MT 的保留价值，消融必须跑够步数**。

## 7. PRISM（arXiv 2603.17074，IBM）

- 规模：3B–24B 七个基座 × 27B 高质量 MT token（饱和点 15–27B），8k ctx 起步。
- **混合消融（Table 5，Granite-3.3-8B）**：Base→Math-only→Math+Code→Math+Code+Science：Math Avg 8.95→36.43→44.99→48.75；Code 2.07→2.81→10.71→10.58；**GPQA 22.56→17.34→19.02→29.12** → 不含科学数据时 GPQA 反而下降；领域数据必须显式进 MT 混合。
- **"放哪一阶段"（§9.6.3）**："Data composition choices matter most at mid-training, not at RL"——科学数据放 MT 解锁 RL 时 +17~28 点 GPQA；RL 侧改混合 <2 点差 → **领域数据的主要收益在 MT 阶段锁定**。
- **引入时机**：MT 放在**长上下文扩展之后**显著优于插进预训练 Phase 3/4（AIME24 9.38/10.00 → 23.59）。
- 上下文与预算：8k→16k 有真实增益（GPQA 34.34→38.89），32k 边际小；15–27B token 即饱和。
- 保留保护：MT 改变 >90% 参数（L2 散度是 RL 的 370–580×）；**MT 后与 base 按 15%/85% 合并再补一段长上下文扩展，RULER 6.46→42.16**。

## 8. OctoThinker（arXiv 2506.20512）

- **200B 恒定 LR 稳定段**（1B/3B/8B = 5e-5/2e-5/1e-5，ctx 8192）+ **20B 衰减段**（cosine 衰到稳定段 LR 的 10%，优于"恒定 10% LR"）。衰减段三支：Long（长 CoT 0.15/0.15）、Short、Hybrid；各支共用 Web-Pro 0.55 + DCLM 0.05 + IF 0.10。
- **QA 占比消融**：>30% QA 收益进入平台，40% 已递减 → 取 30%。
- **长 CoT 副作用**：RL 时"性能骤降 + 响应长度暴涨"（max 拉到 8192）；缓解：复杂模板 + **渐进 max-length 调度（2048→4096→8192 @ 200/320/400 步）**。
- **预算消融**：20B/70B/100B 检查点上，**即使 base 评测已平台化，RL 增益仍随 MT 预算增长** → MT 预算的价值要"看 RL 之后"。

## 汇总：面向网络安全领域（代码+图文交错网页、目标 agentic）的 20–100B token mid-training 建议

**A. 总体配比（CWM 骨架 + CMU 修正）**
- 三段式：**~30% 领域专项 + ~40% 通用代码/仓库级 + ~30% 通用回放**（回放内上采样数学、长上下文与少量指令跟随）。规模缩到 20–100B 时比例不变、体量缩放。网页清洗改写后的图文语料放入"文本-代码 grounding"子类而非回放。
- 专项 30% 内部：① agentless 式非执行数据（漏洞 diff patch → 结构化定位/编辑块，~1/3）；② PR commit packs（修复说明=推理、patch=动作，~1/6）；③ 可执行环境交互轨迹（目标 scaffold 为主 + 少量他 scaffold，不按成败过滤，近重去重，~1/3）；④ 合成定位/推理数据小体量 + **4× 上采样**（Kimi-Dev）。
- **不要指望替代**：CWM Table 4 证明 PR/静态代码不能替代环境交互轨迹；scaffold 间迁移有限 → 轨迹必须用实际评测用的 scaffold 采集。

**B. 阶段划分与时机**
- 若目标含 ≥128K 上下文：两阶段（如 32K×~60% → 128K×~40%），**工具调用与高难数据推迟到第二阶段**；长上下文样本占比随窗口同步提高。若 ≤32K：单阶段即可。
- **领域数据早引入 + 高权重**，不要渐进加码；**MT 放在长上下文扩展之后**（PRISM）。

**C. Loss 设计**
- agentless/PR 配对数据：mask prompt，只监督响应（Kimi-Dev）。
- 环境交互轨迹：**只 mask system prompt，action+observation 联合监督**；观测多样性低时**随机 mask ~50% 观测轮**（CWM）；重复片段一律 mask（Qwen3-Next）。
- 长 CoT 数据：衰减段才引入、配渐进 max-length 调度（OctoThinker）。

**D. 预算与 epoch**
- 每数据集 1–4 epoch，用小模型 scaling-law 模拟 epoching 选点；做**固定后续训练**的 25%/50%/100% 预算消融（Kimi-Dev），且**评测 RL 之后的增益**（OctoThinker）。

**E. 消融与评测协议**
- 8B 级模型做等比例缩放的混合消融（CWM §7.1 方法）；评测**按能力族分组**：领域 agentic 轨迹 NLL + 执行/世界模型理解 + 领域 oracle-patch NLL + 通用保持——单指标会系统性误判。
- 保留效应滞后 ~20k 步才显现，短跑消融会低估；若 MT 后长上下文退化，与 base 15/85 权重合并 + 短长上下文扩展可恢复（PRISM）。

**F. 数据侧优先级（按证据强度）**
1. 可执行环境交互轨迹（目标 scaffold）——唯一直接改善 agentic 表征的数据（CWM）；
2. 内容保持型网页清洗/改写——最便宜的代码能力杠杆（Qwen3-Next，+8.7~12.3 点）；
3. 仓库级组织 + 多序列化格式——优于 file-level；
4. agentless diff→编辑块 + PR 配对——廉价、量大的技能先验（Kimi-Dev）；
5. 合成数据最小必要 + 上采样，禁止以合成为主体（Qwen3-Next 过特化警告）。
