# 调研笔记 02：图文交错数据处理 + 网络安全领域特殊性

> 子任务报告存档，调研日期 2026-09-29。

## A. 图文交错数据处理实践

### A1. OBELICS 基线（141M 文档 / 353M 图像 / 115B token，arXiv 2306.16527）
来源：论文、数据卡 https://huggingface.co/datasets/HuggingFaceM4/OBELICS 、代码 https://github.com/huggingface/OBELICS 。数据卡许可 CC-BY-4.0（需遵守原内容 ToU；opt-out 修复版配置为 `opt_out_docs_removed_2023_07_12`）。

1. 以 Common Crawl WARC/WAT 为源，解析 HTML DOM 并**保序遍历**，在文本序列间按 DOM 顺序插入图像占位，**保留图像-文本相对位置与文档连贯性**；每页一个文档，含 URL 与 WARC 指针（`general_metadata` 字段）。
2. **文档级（而非图像级）过滤**是 OBELICS 核心主张：整页文本质量过滤 + 整页图像过滤，保证训练序列像真实网页。
3. 图像基础四条：分辨率 ≥126×126、长宽比 1:3~3:1、文件 <4MB、单页图像 <25 张。
4. NSFW：CLIP-based NSFW 检测器（LAION-AI/CLIP-based-NSFW-Detector）。
5. 图标/meme/logo：**训练 CLIP 嵌入上的线性分类器**，而非规则匹配。
6. 图像去重：LAION-2B-en 上训练 ViT-B/32，嵌入距离 <~0.05 视为重复，仅保留一张。
7. OBELICS 原版**只用 alt-text、不生成 caption**；IDEFICS2（arXiv 2402.12612）经验：低质量 alt-text 用生成式 caption 替换/增强能提升多模态效果——对安全站（alt-text 常为 "image" 或空）尤其必要。

### A2. 2024–2026 新做法
8. **MINT-1T**（arXiv 2406.11271，代码 https://github.com/mlfoundations/mint-1t）：1T token / 3.4B 图像，新增 **PDF（~106B token）与 arXiv 论文**源；安全 writeup、教材、报告多为 PDF/博客混合，PDF 分支应单列。2025 扩展至 ~1.7T/8.6B 图像。
9. **大规模 re-caption**：用现代 VLM 重写 caption（"What If We Recaption Billions of Web Images with LLaMA-3?" arXiv 2406.08478）已成标配。
10. **文图对齐分数**：RealSyn（ACM MM 2025）的 **RealScore** 可用作"截图-周围文本是否相关"的门控。
11. 文档级质量门：InfiMM-WebMath-40B、AMCrawl 延续 OBELICS 流程新增 KenLM 困惑度；**Primus（安全领域）用 5-gram KenLM 按源分阈值 + MinHash 模糊去重**。
12. 无统一"图文交错比"公开标准；按文档统计 images-per-1000-token 分布并设上下分位截断（MINT-1T/AMCrawl 均报告该统计）。

### A3. 截图/终端图转文字（OCR 分支）
13. 传统 OCR 横评：PaddleOCR 稳定优于 Tesseract（95.2/93.9 vs 92.0/88.4；复杂版面 100% vs 87.5%），速度更快。
14. VLM 直接读图在复杂/不规则文本上已超传统 OCR（GPT-4o、Qwen2.5-VL 最强）。
15. 界面/终端密集解析有新基准 **ScreenParse**（2026-09）。目前**没有针对终端截图的 PaddleOCR-vs-VLM 公开对比**——建议在自有安全截图上抽样建 500–1000 张内部评测集再定引擎。
16. 实操建议：双引擎——PaddleOCR 批量提取终端/代码截图文本（便宜、坐标可还原阅读序）+ VLM 兜底处理拓扑图/流程图（生成结构化描述）；OCR 输出回插原图在交错序列中的位置。

**Primus 清洗管线**（arXiv 2502.11191）：官方 dump+定向爬取（MITRE/Wikipedia 安全类目经 GPT-4o 筛出 375 个/专家 CTI）→ dom-to-semantic-markdown → KenLM 5-gram 困惑度按源阈值 → MinHash（5-gram、112 hash、14 桶、≥75%）→ C4 行/文档过滤（保留代码花括号行、跳过"终端标点"规则）→ 逐源手工启发式 → 低质页 LLM 改写增广。

### B2. 双用途过滤规则草案
依据：CyberSecEval 2 分类学（arXiv 2404.13161：prompt injection 15 类、漏洞利用、按 MITRE ATT&CK 映射的 attack helpfulness，以及 **FRR（误拒率）与 borderline 良性集**概念）；**Primus 的教训（CPT 后 Garak malwaregen 14.3%→29.0%，且语料层零过滤）**；SecGPT 反例（全无过滤）。

草案（文档级判定，不切句）：
1. **默认保留**：CTF writeup（靶场语境）、漏洞机理与 CVE 分析、patch/diff、检测规则（YARA/Sigma/Snort）、加固与蓝队内容、工具文档、CTI 报告——对应 CyberSecEval "borderline benign"（合法端口扫描等不得误杀）。
2. **移除**：可直接执行的武器化物——恶意软件样本/源码与免杀、shellcode 库、活跃 C2 配置与基础设施（IP/域/DGA）、DoS/僵尸网络工具链、钓鱼 kit。
3. **脱敏保留**：凭据类（PEM 私钥、AWS AKIA…、password/cookie 字样）删除或打码；未修补 0day 的可运行 PoC → 保留"漏洞描述+防护视角"，移除 weaponized 代码；exploit-db 类页面以摘要替代完整源码。
4. **图像分支同样过检**：终端/截图 OCR 文本并入同一正则库；补丁对比图、拓扑图默认无害。
5. **阈值校准用 FRR**：自建 ~200 条 borderline 良性集（扫描、取证、逆向教学）量误杀率，参照 CyberSecEval2（多数模型 FRR<15%，过杀重创领域效用）。
6. **LLM-judge 三轴打分**：意图证据 + ATT&CK 战术 + 是否含 operational detail（可运行/可直接部署），而非关键词黑名单。

### B3. 评测污染与去污染
污染面：cybench 40 题全公开、NYU CTF 200 题+官方 writeups 公开、InterCode-CTF 基于 picoCTF（writeup 大规模公开、污染风险最高）；CyberSecEval 提示词公开；τ²-Bench/BFCL 公开任务+代码可被语料复述。**安全博客常直接复述赛题解法，writeup 语料天然高污染**。

去污染做法：
1. **n-gram**：13-gram 归一化（小写/去标点/空白折叠）重叠即判污染——GPT-3/EleutherAI 事实标准；Primus 实测对 CISSP N=9~13 零重叠。
2. **MinHash 模糊去重**先于 n-gram，清近似转写。
3. **嵌入方法**补释义级泄漏：句/文档向量余弦 >~0.8–0.85 送 LLM 复核（LLM Decontaminator + Clean-Eval，arXiv 2404.00699）。
4. **图像分支**：writeup 截图常含 flag/终端输出——OCR 文本进同一 n-gram 污染库。
5. 终解：对内评测尽量用私有 held-out 新题（Terminal-Bench 式），公开基准仅作参考。

## 落点建议
图像分支照 OBELICS 四条基础过滤 + CLIP 分类器去图标/meme + 去重骨架，叠加：alt-text 缺失时 VLM caption（安全站常态）、拓扑/流程图 VLM 结构化描述、PaddleOCR+VLM 双引擎 OCR（自建终端截图评测集定阈值）；文档保留交错结构以服务 agentic 目标；文本侧照 Primus 管线；全库叠加双用途规则与三层去污染。
